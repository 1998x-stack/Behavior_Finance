# 仓库架构与内容工程规范

## 1. 目标架构

当前仓库采用“课程目录稳定、内容格式双轨、公共设计系统逐步抽离”的渐进式架构。第一阶段不大规模移动旧文件，避免破坏 Markdown/HTML 相对链接和 GitHub Pages URL；先统一规范，再按模块迁移。

~~~text
课程层（00–07）
  ├── lesson.md       # 课程知识源与长文笔记
  └── lesson.html     # 阅读体验、图解与交互
共享表现层
  ├── style.css       # 首页与站点基础样式
  ├── markdown.css    # 课程正文排版
  └── markdown.js     # 正文增强
工程层
  ├── main.py         # audit / init / backup / verify-backup
  ├── tests/          # 内容保护与回归测试
  └── .github/        # CI
治理层
  └── docs/           # 架构决策、PDF映射、路线图、质量规范
~~~

## 2. 内容类型与责任边界

| 类型 | 位置 | 职责 | 完成标准 |
|---|---|---|---|
| 正式课程 | 00_*–07_* | 对应课程主线 | 目标、机制、证据、应用、边界完整 |
| 扩展笔记 | 对应模块目录 | 补充概念或方法 | 标注扩展性质及关联课程 |
| 页面资源 | assets/（后续引入） | SVG、局部脚本、图片 | 有来源/许可记录、可离线加载 |
| 研究文档 | docs/ | 规范与治理 | 不混入读者课程正文 |
| 测试 | tests/ | 内容与构建回归 | 可重复运行，不依赖真实用户数据 |

## 3. 稳定 ID 与命名

- 保留现有目录、文件名和章节编号，避免无必要的 URL 变化。
- 新课程采用 NN_章节号_主题_slug.md/html 成对命名。
- 新增概念、案例和实验应有稳定短 ID，例如 prospect-theory-value-function。
- 文件名表达主题；标题表达读者问题；不要把临时状态写进文件名。
- 删除、合并或重命名页面前，先检查所有相对链接、README、首页、测试与外部链接。

## 4. 每篇专题的内容模型

每页建议包含以下语义区块（不要求所有文章机械套用相同长度）：

1. 开场问题与一句话结论。
2. 学习目标与必要先修概念。
3. 现实决策情境。
4. 核心机制图（SVG，含 title/desc/figcaption）。
5. 理论定义、公式、变量解释与假设。
6. 经典实验/论文证据（来源、样本、方法、结果、局限）。
7. 金融市场案例（区分事实、解释与推论）。
8. 交互实验或可复现小模拟（标注 toy/synthetic）。
9. 实践检查清单。
10. 常见误解、适用边界与延伸阅读。

## 5. HTML 设计系统

遵循 Olah-style-posts 的教学叙事原则，而非复制其资产：

- 先提出认知冲突，再逐步展示机制；每张图回答一个问题。
- 使用语义结构：skip link、nav、main、article、section、figure、figcaption。
- 每页一个 H1，H2/H3 层级反映学习顺序。
- 桌面正文阅读宽度约 760–840px；目录可侧栏固定，移动端折叠或置顶。
- 关键图形以原创 SVG 绘制，提供可读标签和文字说明。
- 交互控件使用原生 button/input/select，支持键盘、焦点和 reduced-motion。
- 公式使用语义 MathML 或可靠的离线呈现；避免依赖未固定 CDN 脚本。
- 360px/390px 手机视口不允许页面整体横向溢出；宽公式仅在自身容器滚动。
- 打印样式应保留正文、图表和出处。

## 6. 证据与模型规范

每个重要主张归入以下类别之一：source-claim（原作者主张）、replication（独立复现）、derived（推导）、illustrative（教学示例/合成数据）、hypothesis（待检验解释）。

量化结论必须说明数据、样本期、基准、计算口径和出处。模型图与公式必须写出关键假设；原始前景理论与累积前景理论、理论预测与经验事实、历史策略表现与未来收益不可混为一谈。

## 7. 脚本和工程约束

- main.py audit 只读；init 仅独占创建缺失文件；备份必须带 SHA-256 清单。
- 任何生成器都不得静默覆盖人工编辑的课程文件。
- 新脚本必须有临时目录测试、错误路径测试和重复运行测试。
- 页面 JS 尽量渐进增强；无 JS 时仍可阅读全部核心知识。
- 不引入不必要的远程字体、脚本、跟踪器或运行时依赖。
- GitHub Actions 使用最小权限；变更按批次提交并检查 diff。

## 8. 目录迁移策略

当前课程文件分散在模块目录中，第一轮不移动。待所有页面的导航和资源路径建立自动检查后，再考虑将公共静态资源整理到 assets/css、assets/js、assets/figures。迁移需同时提供旧 URL 兼容策略或明确的重定向/链接更新。
